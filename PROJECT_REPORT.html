1Summary

The foundation is complete and tested on real evidence. The project now holds an evidence database organised by case: each investigation groups its computers, phones and USB drives with the documents that describe it. The first agent, the MultimodalVisionAgent, reads EXIF metadata, runs OCR and a vision-language model on images, links what it finds to the case briefing, and writes a report. Every claim it makes is re-executed against the evidence file by the verifier before it is accepted.

Tested result. On the M57-Patents case (4 Windows PCs, 4 USB drives) the agent examined 40 images in 250 s and produced 41 verified findings and 0 rejected. On the Android 10 reference phone it produced 9 verified and 0 rejected, matching the Sprint 1 proof of concept exactly. Peak GPU memory was 5.5 GB.

A local web console (python main.py gui) shows each agent step live: OCR boxes over the image, metadata, the model's answer, every claim and its verification, and the links to the briefing. A dataset export turns the whole database into tables ready for machine-learning work, split by case.

The zero-hallucination contract

An agent never asserts a fact on its own authority. Each finding carries citations: the file, an exact locator (byte offset, line number, SQL query, regex or EXIF tag), the file's SHA-256 and the expected text. The verifier opens the file again, re-runs the locator and compares. Model-read text (OCR, VLM) counts only when a database cell or text line in the evidence explains at least 85% of it.

StatusMeaningUsed as evidence?
verifiedEvery citation was re-executed and matched.Yes. The only evidentiary status.
rejectedA citation failed: wrong value, changed file, invalid query.No. Treated as a hallucination signal.
uncorroboratedA model observation with no ground truth (e.g. a scene description).No. Kept as labelled context only.

How the data was acquired

  • All sources are public research and teaching images from Digital Corpora and NIST CFReDS.
  • Disk images up to 45 GB were downloaded with parallel range requests (about 30 MB/s) and deleted after extraction. Owl HD1 (68 GB) was read in place: 31.9 GB transferred in 79 minutes.
  • Every file is recorded with its SHA-256, original path, MACB times and inode; deleted recoveries are flagged with a reliability note.
  • Credential stores are never copied: SAM, SECURITY, /etc/shadow, keychains, password files, pagefile and hibernation files.
  • Digital Corpora's Lone Wolf and Narcos teacher guides are password-protected for instructors. They were not opened; a note in each case says where to place them if the password is obtained.

How the context comparison works

LinkRule
corroboratesA verified finding contains a person, e-mail, phone, file name or device named in the brief.
keyword matchWeaker: a verified finding contains a recurring keyword of the brief.
outside timeframeA verified timestamp falls outside the period the brief describes.
not in contextA verified camera model the brief never mentions.
new leadA verified GPS position or confirmed text with no counterpart in the brief.
unverified mentionA model observation mentions a brief entity. Follow up; not evidence.

The context is built only from the brief, never the answer key, so the agent cannot simply find what it was told the answer is. Links are saved to workspace/memory.json after every image and never change a finding's verification status.

6The web console

Start it with python main.py gui and open http://127.0.0.1:8765. It binds to localhost, serves evidence through the sandbox, and shows answer-key text only after an explicit “reveal” click.

Live agent

  • Start a run on any case and choose evidence items, image count, OCR and VLM.
  • Step feed: EXIF, OCR, index lookups, model answer, claims, verification, context links.
  • Image viewer with OCR boxes: green when backed by evidence, amber when not, dashed when ignored.
  • Context panel: what the agent was told, and the links it draws for the current image.

Other views

  • Memory: brief entities with sources, and every link, filterable.
  • Findings: status, claim, citations and context per run.
  • Report: the rendered Markdown report.
  • Documents: brief, acquisition logs, locked answer key.
  • Evidence: categories, file systems, acquisition MD5, top images.

Learning tasks this data supports

Ready now

  • Artefact classification: 21 file categories across 6 platforms.
  • Corroboration scoring: learn which OCR/VLM text will verify, from the 898 labelled findings (grows with every run).
  • Image triage: rank evidence images by relevance (user photo, screenshot, document scan, cache).
  • Timeline anomaly detection: 1.41 M MACB entries, including deleted and post-CCleaner states.

Needs labels first

  • Case question answering: brief in, answer key as the reference. NIST and M57 have the best keys.
  • Entity linking across devices (same person on phone and PC).
  • Relevance labels per file from the Lone Wolf tagged-file listings and answer keys.
  • Deduplicate by SHA-256 (duplicate_of) before training.

9First steps (next session)

In order, before new agents are added:

  1. Put the project under version control. git init, ignore .venv/, data/cases/, data/datasets/, data/_spool/, data/outputs/. Recreate the venv to fix the stale launchers.
  2. Fix the three medium issues. Independent verifier bridge without hash cache, WAL/journal hashing in citations, a self-test that works on any case. Keep 0 rejected on real data.
  3. Run the vision agent across every case. python main.py investigate --case <id> --limit 25 for all 18 cases. This grows the labelled findings table from 898 to several thousand rows.
  4. Index document text. DOCX/PDF text with citable locators, so OCR can be confirmed against office documents on the Windows images.
  5. Refresh catalogue and dataset. python main.py cases catalog and python main.py dataset; check the datasheet totals.
